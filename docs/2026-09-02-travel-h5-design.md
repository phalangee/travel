# 旅行行程 H5（travel-h5）设计文档

日期：2026-09-02
状态：待用户审核

## 1. 背景与目标

用户（自用，家庭出游，含 2 岁半宝宝）希望有一个手机上好用的旅行行程工具，替代纸面攻略。首个行程为 2026.9.23–10.5 新疆北疆自驾 13 天（数据来源：DeepSeek 对话整理的最终版行程）。

核心目标：

1. 手机优先的行程浏览体验：按天划卡，一天一屏。
2. 每天内容完整覆盖：行程总览、时间轴、三餐/美食、购物建议、衣物与随身物品提醒、门票/预约提醒、亲子注意事项。
3. 地图可视化：全程路线图 + 每日路线图，关键地点（住宿/景点/餐饮/换乘）分色标注，支持一键在高德 App 打开导航。
4. 通用模板 + 可积累：页面与数据彻底分离，换行程 = 换数据文件；首页陈列所有去过的旅行，形成足迹地图。
5. 零成本运行：纯静态站，GitHub Pages 托管（`https://phalangee.github.io/travel/`），无服务器、无域名、无备案。

非目标（本期不做）：

- 后台编辑功能（更新方式采用方案 A：用户把攻略发给 AI，解析成数据文件后更新页面）
- 用户系统、云同步、社交分享
- 网页内实时导航（跳转高德 App 代替）
- 地图瓦片的完全离线保证（详见 6.3 风险）

## 2. 技术方案

**无构建纯静态站**：HTML + CSS + 原生 JS + JSON 数据文件，无框架、无打包工具。更新流程 = 改文件 → `git push` → GitHub Pages 自动生效。选择理由：自用、更新链路最短、长期可维护性最好（不依赖 Node 生态）。

目录结构：

```
travel-h5/
├── index.html            # 入口：旅行主页（足迹地图 + 旅行封面卡列表）
├── trip.html             # 单次旅行页（行程划卡）
├── css/                  # 样式（移动优先）
├── js/                   # 渲染与交互逻辑
├── data/
│   ├── trips.json        # 旅行索引（列表、封面、状态）
│   └── trips/
│       └── xinjiang-2026.json   # 每趟旅行一份行程数据
├── assets/               # 图标等静态资源
├── manifest.webmanifest  # PWA 清单
├── sw.js                 # Service Worker（离线缓存）
└── docs/                 # 本文档及数据格式说明
```

地图：高德开放平台 JS API 2.0（Web 端 Key，由用户申请后填入配置）。Key 放在 `js/config.js`，`.gitignore` 不排除（个人自用仓库，无敏感数据风险；若用户未来开源再改为占位符）。

路由：静态站无法做真路由，采用 query 参数（`trip.html?id=xinjiang-2026&day=3&tab=plan`），支持分享/收藏直达某天。

## 3. 信息架构与交互

### 3.1 旅行主页（index.html）

- 顶部：足迹地图（高德地图，所有去过的目的地打点）。
- 下方：旅行封面卡列表（封面图、标题、日期范围、天数、状态标签「计划中/进行中/已完成」）。进行中的旅行自动排在最前并高亮「今天」。
- 点封面卡进入 trip.html。

### 3.2 旅行页（trip.html）

- 顶部：全程路线缩略图（可点击展开为大图）+ D1~Dn 日期条（横向滚动，显示「今天」标记）。
- 主体：**一天一屏的横向滑动划卡**（touch 滑动 + 日期条点击均可切换）。
- 每张日卡结构：
  - 日总览卡：日期/星期、起点→终点、住宿地与推荐酒店、驾驶总时长、当日强度（轻松/中等/辛苦，按驾驶+游玩时长自动标注）、核心景点摘要、当日路线小地图（点击放大）。
  - Tab 页（固定 3 个）：
    - **行程**：竖向时间轴（时间点 + 事项 + 车程/游玩时长 + 备注），含沿途风景说明。
    - **美食**：三餐推荐（早/午/晚）、适合带宝宝的选项、当地特色、城市购物建议（如吐鲁番干果、大巴扎采购）。
    - **准备**：衣物/天气提醒、随身包物品清单、当日门票/预约/证件提醒（如边防证、博物馆预约）、加油/补给提醒、亲子注意事项。
  - Tab 内容按数据有无自适应显示，某天无内容则显示空态或隐藏该模块。

### 3.3 地图交互

- 标记分四色：住宿（蓝）、景点（橙）、餐饮/购物（红）、换乘/停车（灰）。
- 点击标记显示信息窗（名称、地址、备注、「在高德打开」按钮）。
- 「在高德打开」使用 `https://uri.amap.com/marker?position=lng,lat&name=xxx` 或导航 URI，唤起高德 App；未安装则打开网页版。
- 路线绘制：点间连线示意（polyline + 途经顺序），非导航级精确路线；精确导航交给高德 App。

## 4. 数据模型（JSON）

`trips.json`（索引）：

```json
{
  "trips": [
    {
      "id": "xinjiang-2026",
      "title": "新疆北疆自驾",
      "subtitle": "带娃的秋日北疆环线",
      "startDate": "2026-09-23",
      "endDate": "2026-10-05",
      "cover": "assets/covers/xinjiang-2026.jpg",
      "status": "planned"  // planned | ongoing | done
    }
  ]
}
```

`trips/xinjiang-2026.json`（单次行程，字段均可选、按需出现）：

## 5. 移动端适配

- 移动优先：按 375–430px 竖屏设计；基础字号 ≥15px，正文 16px；点击目标 ≥44px 高。
- 横向划卡用 scroll-snap 实现（原生滚动，回弹手感好，无需手势库）。
- 桌面（>768px）：内容居中限宽 720px，两侧留白，地图与划卡不强行拉宽。
- 安全区适配：iOS 刘海/底部小黑条（safe-area-inset）。
- 开发过程中用手机视口截图逐屏自检；上线前用户真机验收。

## 6. PWA 与离线

- manifest.webmanifest：名称「我的旅行」、独立图标、standalone 显示模式，支持添加到主屏幕。
- Service Worker 策略：App Shell（HTML/CSS/JS）与行程 JSON 精确缓存、优先离线；高德 JS API 脚本按需缓存；地图瓦片不做强缓存（体积不可控），离线时地图区域降级显示地点列表 + 文字地址。
- 版本更新：sw.js 内版本号变更触发后台更新，用户下次打开生效。

## 7. 部署与更新流程

1. 用户在 GitHub 新建公开仓库 `travel`（引导操作，约 5 分钟）。
2. 本地 `travel-h5/` 目录 `git init`、提交、推送，GitHub Pages 开启 main 分支。
3. 访问地址：`https://phalangee.github.io/travel/`。不影响现有博客仓库。
4. 后续更新（方案 A）：用户把新攻略发给 AI → AI 生成/更新 `data/trips/*.json` → 推送 → 自动生效。

## 8. 测试与验收

- 数据校验：写一个零依赖的校验脚本（Node 或纯 HTML 工具页），检查 JSON 字段完整性、日期连续性、坐标格式。
- 功能自测清单：主页渲染、进入行程、划卡切换、Tab 切换、地图加载与标记点击、跳高德、PWA 安装提示、离线打开。
- 跨端验证：iOS Safari（用户真机）、Android Chrome（用户真机）、桌面 Chrome。
- 高德 Key 未就绪阶段：使用「无 Key 降级模式」——地图区域显示静态示意（地点列表 + 顺序连线 SVG），保证整站可先行验收。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 山区/沙漠无网络，地图加载失败 | 地点带文字地址，支持跳高德 App；PWA 缓存行程数据 |
| 高德免费配额超限（个人自用概率极低） | 日调用配额充足；超限仅影响地图，文字行程不受影响 |
| GitHub Pages 国内访问偶发慢 | 静态资源小（<2MB 除封面图）；封面图压缩；可接受 |
| 行程数据有误（如原文「14天」实为13天） | 解析时校准：本行程按 D1–D13 共 13 天、吐鲁番 2 晚（D9/D10）、乌鲁木齐 D1/D11/D12 共 3 晚计 |
| 长期浏览器兼容性 | 只用稳定特性（scroll-snap、ES2020），不追新 API |
